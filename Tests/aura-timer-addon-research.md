# Aura timer addon research: secret durations and minutes-only text

Research date: 2026-11-14. Scope: preserve a live, accurate `105m` display during combat on Forever, including aura changes during combat. This is source research, not an in-game verification report. No addon runtime was changed. No commits or pushes were made.

## Finding and recommendation

**There is a concrete native formatting route on the inspected Forever source: a custom aura button's `SetDurationText(fontString, { textFormatter = formatter })`.** Blizzard internally attaches a `DurationTextBinding`, supplies the real aura duration, and refreshes it as the aura changes. A private native formatter can keep minutes as the largest unit, without addon Lua dividing a secret number. BetterBlizzFrames ships this custom aura-button architecture in its Forever module, and oUF exposes its formatter option directly. This is strong implementation evidence, **not proof that BuffTimers already works with this route or that `105m` has been verified in Forever combat**. Sources: [Forever custom aura button, lines 178 onward](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraButton.lua#L178), [BetterBlizzFrames Forever styling](https://github.com/Bodify/BetterBlizzFrames/blob/64dba51f651a04eee8412707016b665abcd2fc82/forever/modules/auras.lua#L1001), [oUF formatter integration](https://github.com/oUF-wow/oUF/blob/911c218ee671544630f4a174795a8c58a62f34ab/elements/auras.lua#L179).

The decisive distinction is **configuring a native renderer with public settings and an opaque duration object**, versus **calling `FormatNumber(secretSeconds)` from addon execution**. The latter remains restricted. Do not claim that merely creating a formatter, calling `securecall`, or wrapping a failing formatter call in `pcall` solves this. [Forever NumericFormatter API](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_APIDocumentationGenerated/NumericFormatterAPIDocumentation.lua), [DurationTextBinding API](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_APIDocumentationGenerated/DurationTextBindingObjectAPIDocumentation.lua).

Recommended investigation order:

1. Probe an addon-owned `DurationTextBinding` with an obtainable real player-aura duration object. This offers the smallest potential change to BuffTimers, but access during combat and lifecycle integration remain unresolved.
2. If public aura access is denied or the existing Blizzard button provides no supported binding hook, use the supported custom `AuraContainer` / custom aura-button route. This is the strongest source-supported architecture, but is a larger change than a text post-hook.
3. Retain the existing compact-native-text fallback on builds lacking the required APIs. That fallback cannot promise `105m` if Blizzard supplied `2h`.

## What the Blizzard implementation actually permits

### Existing BuffFrame and the missing conversion

Forever's existing `AuraButtonMixin:OnUpdate` calls `securecall(self.UpdateDuration, self, self.timeLeft)`; `UpdateDuration` invokes `SecondsToTimeAbbrev`. `TimeUtil.lua` chooses days/hours/minutes using its own thresholds. BuffTimers currently post-hooks duration rendering and removes spaces for secret values. Once the native result has rounded into hours, removing spaces does not restore lost minute precision. A text-only hook also does not acquire an untainted execution context simply because Blizzard called its original method securely. [Forever BuffFrame](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_BuffFrame/BuffFrame.lua#L1271), [TimeUtil](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_SharedXML/TimeUtil.lua), [existing local verification](forever-combat-verification.md).

### Native DurationTextBinding

Forever already documents `C_DurationUtil.CreateDurationTextBinding()`. The binding has `SetDuration`, `SetFontString`, `SetFormatter`, `SetEnabled`, `SetUpdateInterval`, and `SetTextColorCurve`. Its purpose is automatic font-string updates from a duration object. `GetFormattedText` is conditionally secret: the API is a renderer, not a declassification mechanism. Several setters are annotated `SecretArguments = "AllowedWhenUntainted"`; do not feed them secret scalar arguments from addon Lua. A public object reference containing secret duration state must not be conflated with passing a secret scalar directly. Actual taint behavior of a standalone binding still needs a client probe. [DurationUtil](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_APIDocumentationGenerated/DurationUtilDocumentation.lua), [binding API](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_APIDocumentationGenerated/DurationTextBindingObjectAPIDocumentation.lua).

Most importantly, Blizzard's **custom aura button** implements the safe handoff itself. `SetDurationText` validates and initializes the inbound font string, adds secret aspects for text/alpha/color, configures the internal binding, and accepts a custom `textFormatter` or `textFormat`. `ApplyDurationText` later supplies the aura duration and enables the binding when appropriate. The internal binding persists across reconfiguration. [SetDurationText](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraButton.lua#L178), [persistent binding](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraButton.lua#L395), [duration updates](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraButton.lua#L607).

**Objection to a simple retrofit:** `CustomAuraButtonSharedMixin:SetDurationText` is not the same API as legacy `AuraButtonMixin:UpdateDuration`. Do not assume the existing BuffFrame button has `SetDurationText`, copy private methods onto it, or call custom-button internals on an unrelated frame. The custom route owns aura assignment and refresh, which the old post-hook does not. The legacy and custom implementations coexist in this Forever source. [legacy button](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_BuffFrame/BuffFrame.lua#L1425), [custom button](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraButton.lua#L178).

### A minutes-only formatter

Two concrete formatter configurations are supported by the inspected API definitions:

* **SecondsFormatter:** create a private `C_StringUtil.CreateSecondsFormatter()`, use `OneLetter`, `SetDesiredUnitCount(1)`, `SetMaxInterval(Enum.SecondsFormatterInterval.Minutes)`, and disable interval promotion with `SetCanRoundUpIntervals(false)`. Use a seconds minimum if sub-minute seconds are desired, or a minutes minimum for a literal all-minutes mode. Set whitespace stripping explicitly; `StripIgnoreLocale` is the mode that always removes spacing, while `Strip` can preserve it for certain locales. Check rounding and the exact 60-minute boundary in-game. These are API-supported settings, but the precise `105m` result has not been observed in this research. [SecondsFormatter methods](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_APIDocumentationGenerated/SecondsFormatterAPIDocumentation.lua), [enum and locale semantics](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_APIDocumentationGenerated/SecondsFormatterSharedDocumentation.lua).
* **NumericRuleFormatter:** configure a native minute rule with `format = "%dm"` and `components = {{ div = 60, step = 1, rounding = Enum.NumericRuleFormatRounding.Up }}`. Keep any desired seconds rule below it and omit hour/day breakpoints. The division and rounding occur inside the native formatter. This gives explicit ceiling-minute semantics without relying on SecondsFormatter promotion behavior. `Up` is appropriate only if that matches BuffTimers' intended rounding. A literal `m` is not localized; choose the project's intended suffix policy. [numeric-rule structures](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_APIDocumentationGenerated/NumericRuleFormatterSharedDocumentation.lua), [tullaCTC minute rule](https://github.com/tullamods/tullaCTC/blob/a20c99c2eab0305613c7f3e85acf332bd264301f/tullaCTC/themer.lua#L100).

Pass that formatter to the native binding or cooldown renderer. **Do not call `formatter:FormatNumber(secretSeconds)` yourself.** Do not mutate `AuraContainerInbound.GetDefaultAuraDurationFormatter()` globally: it returns the shared default object. Blizzard's default formatter uses a step curve that promotes intervals around 1.5 times their ordinary size, so leaving it unchanged does not achieve minutes-only output. [default formatter construction](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainerShared.lua#L74), [default object getter](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_AuraContainer/Blizzard_AuraContainerInbound.lua#L5).

## Addon findings and objections

### BetterBlizzFrames: strongest Forever architecture evidence

The [Camelot TOC](https://github.com/Bodify/BetterBlizzFrames/blob/64dba51f651a04eee8412707016b665abcd2fc82/BetterBlizzFrames_Camelot.toc) declares `16001` and explicitly loads `shared/timerFormatter.lua` plus `forever/modules/auras.lua`. The Forever module creates a `CustomAuraContainerTemplate` at line 1815. Player duration text is attached through `button:SetDurationText(...)` at line 1026. For nonplayer aura cooldown text, `ApplyCountdownFormatter` supplies the custom native formatter. Sources: [Forever aura implementation](https://github.com/Bodify/BetterBlizzFrames/blob/64dba51f651a04eee8412707016b665abcd2fc82/forever/modules/auras.lua#L960), [container creation](https://github.com/Bodify/BetterBlizzFrames/blob/64dba51f651a04eee8412707016b665abcd2fc82/forever/modules/auras.lua#L1815).

It also directly creates a `DurationTextBinding` for temporary-enchant cells, attaches a created duration object and font string, updates that duration object with `SetTimeFromEnd`, and toggles the binding with visibility. This proves an actual addon uses the object/binding lifecycle on its Forever code path, but **those enchant times are not evidence of successful secret aura inputs**. [imbue creation and painting](https://github.com/Bodify/BetterBlizzFrames/blob/64dba51f651a04eee8412707016b665abcd2fc82/forever/modules/auras.lua#L4044).

Its [shared numeric formatter](https://github.com/Bodify/BetterBlizzFrames/blob/64dba51f651a04eee8412707016b665abcd2fc82/shared/timerFormatter.lua) uses native `div`, `step`, and `Up` rounding. It still includes hour/day rules, and its player text uses the default formatter unless overridden. **Do not report that BetterBlizzFrames itself preserves `105m`; it demonstrates the transport and rendering architecture, not the requested policy.**

### tullaCTC: native rules, with an explicit minutes policy

[themer.lua](https://github.com/tullamods/tullaCTC/blob/a20c99c2eab0305613c7f3e85acf332bd264301f/tullaCTC/themer.lua) builds a `NumericRuleFormatter`, supplies breakpoints, and calls `cooldown:SetCountdownFormatter(formatter)` rather than continuously calculating secret remaining time in Lua. Its minute rule divides by 60 in native components. Hour/day/week rules are conditionally added, making omission of larger units a concrete adaptation. Its [TOC](https://github.com/tullamods/tullaCTC/blob/a20c99c2eab0305613c7f3e85acf332bd264301f/tullaCTC/tullaCTC.toc) includes `16001`; its [changelog](https://github.com/tullamods/tullaCTC/blob/a20c99c2eab0305613c7f3e85acf332bd264301f/CHANGELOG.md) documents adoption of `SetCountdownFormatter`.

Objection: this styles a **Cooldown widget**, not an arbitrary existing BuffFrame font string. BuffTimers would need a correct duration source and widget integration, or use the same formatter through `DurationTextBinding`. The formatter alone does not obtain a hidden aura duration.

### ElvUI: duration objects plus native cooldown formatting

[ElvUI.toc](https://github.com/tukui-org/ElvUI/blob/74dc698f73f02d01ac409ce830e9b2fd191f86eb/ElvUI/ElvUI.toc) includes `16001` and a `camelot` load path. [Auras.lua](https://github.com/tukui-org/ElvUI/blob/74dc698f73f02d01ac409ce830e9b2fd191f86eb/ElvUI/Game/Shared/Modules/Auras/Auras.lua#L396) gets an aura duration object and feeds `SetCooldownFromDurationObject`. [General/Cooldowns.lua](https://github.com/tukui-org/ElvUI/blob/74dc698f73f02d01ac409ce830e9b2fd191f86eb/ElvUI/Game/Shared/General/Cooldowns.lua#L149) builds native numeric rules and assigns a countdown formatter. Larger-unit rules are present, so copying the default rules does not preserve minutes-only formatting.

Objections: some aura-container styling explicitly clears the countdown formatter when setting text colors, so integration order matters. Also public `GetAuraDuration` access is not guaranteed just because an addon source calls it; the current API carries restrictions. [Containers.lua](https://github.com/tukui-org/ElvUI/blob/74dc698f73f02d01ac409ce830e9b2fd191f86eb/ElvUI/Game/Shared/Modules/Auras/Containers.lua#L313).

### oUF: clearest custom aura formatter handoff

[elements/auras.lua](https://github.com/oUF-wow/oUF/blob/911c218ee671544630f4a174795a8c58a62f34ab/elements/auras.lua#L179) passes `binding`, `textFormatter`, `textFormat`, and `textColor` options directly into `button:SetDurationText`. This provides a concise reference for connecting a private formatter to Blizzard-owned aura updating. It is architectural source evidence, not an independent Forever combat recording.

### ShadowedUnitFrames: confirms an access failure must be handled

The maintained NoSelph fork's [TOC](https://github.com/NoSelph/ShadowedUnitFrames/blob/a85fe75e4606c67cfe72aa9cb75e4882bffea1d7/ShadowedUnitFrames.toc) includes Forever. [renderAura](https://github.com/NoSelph/ShadowedUnitFrames/blob/a85fe75e4606c67cfe72aa9cb75e4882bffea1d7/modules/auras.lua#L2068) wraps `C_UnitAuras.GetAuraDuration` in `pcall`, uses `SetCooldownFromDurationObject` on success, and hides the cooldown on failure. The source comments identify the unit-aura-access restriction. This is evidence against promising that every addon can retrieve every secret aura during combat. It is not a minutes-only solution.

### OmniCC: old parsing workaround is not a reliable solution

The inspected [cooldown.lua](https://github.com/tullamods/OmniCC/blob/81e0891abd044516f0a300fc6043f9870e99f96a/OmniCC/core/cooldown.lua#L647) creates a proxy cooldown, reads its rendered text, and parses numbers or English `m/h/d` suffixes. Its comment assumes cooldown text is not secret. The derived number drives OmniCC's Lua timer. [timer.lua](https://github.com/tullamods/OmniCC/blob/81e0891abd044516f0a300fc6043f9870e99f96a/OmniCC/core/timer.lua#L179) performs arithmetic and comparisons.

Objections: the source predates the inspected modern APIs; secret text cannot safely be inspected with Lua matching, table keys, truth tests, or `tonumber`; suffix parsing is locale-sensitive; and rounded `2h` cannot reveal whether the actual remainder is 105 or 119 minutes. New custom aura text explicitly has the Text secret aspect. Treat this as historical source, not a proven Forever-compatible escape hatch. Prefer the same author's newer tullaCTC native-rendering design.

### Raven and Masque: no transferable secret-minute solution found

The inspected Raven fork's [Nest_FormatTime](https://github.com/Dicebar/Raven/blob/3350b8d663d8cc3733d384590173c96a82c58c03/Nest.lua#L2913) performs Lua `math.floor`, division, and duration comparisons. Searching that checkout found no `issecretvalue`, `CreateDurationTextBinding`, or `SetCountdownFormatter` implementation. It is useful for readable timers, not evidence for handling secret durations. This finding is deliberately limited to that fork.

Masque's [text region handler](https://github.com/StormFX/Masque/blob/638ede870223a8fa6a3d248410e566903f3ab3d3/Core/Regions/Text.lua) sets alignment, wrapping, size, layer, and position. Its [cooldown handler](https://github.com/StormFX/Masque/blob/638ede870223a8fa6a3d248410e566903f3ab3d3/Core/Regions/Cooldown.lua) skins the region. No `SetCountdownFormatter` or `CreateDurationTextBinding` use was found in its Lua source. Masque integration can style the result but does not supply the duration conversion.

## Compatibility and remaining risks

Both inspected Blizzard branches, Forever `bebcb6bf309c` and Retail `297d7aaaa736`, contain the custom `SetDurationText` handoff, `DurationTextBinding`, and the maximum-interval formatter setting. This is direct Forever evidence; it does not rely on assuming Retail patch numbers map to Forever interface numbers. On older installed builds, feature-detect the actual APIs and frame types. [Retail custom button](https://github.com/Gethe/wow-ui-source/blob/297d7aaaa736f346b3e036f38ee088eaf7f8c07f/Interface/AddOns/Blizzard_AuraContainer/Blizzard_CustomAuraButton.lua#L178), [Retail binding](https://github.com/Gethe/wow-ui-source/blob/297d7aaaa736f346b3e036f38ee088eaf7f8c07f/Interface/AddOns/Blizzard_APIDocumentationGenerated/DurationTextBindingObjectAPIDocumentation.lua), [Retail formatter](https://github.com/Gethe/wow-ui-source/blob/297d7aaaa736f346b3e036f38ee088eaf7f8c07f/Interface/AddOns/Blizzard_APIDocumentationGenerated/SecondsFormatterAPIDocumentation.lua).

The main unresolved small-change approach is obtaining an opaque duration object for the original BuffFrame button. `C_UnitAuras.GetAuraDuration` has `RequiresUnitAuraAccess`, `RequiresValidUnitAuraInstance`, and secret-argument restrictions on **both** inspected branches. Constructing a new duration object with secret scalar expiration/duration values is not a supported workaround: `SetTimeFromEnd` and `SetTimeFromStart` are also `AllowedWhenUntainted`. The custom container route avoids requiring addon Lua to read those scalars. [Forever unit aura API](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitAuraDocumentation.lua#L286), [Retail equivalent](https://github.com/Gethe/wow-ui-source/blob/297d7aaaa736f346b3e036f38ee088eaf7f8c07f/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitAuraDocumentation.lua), [duration object API](https://github.com/Gethe/wow-ui-source/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_APIDocumentationGenerated/LuaDurationObjectAPIDocumentation.lua).

Precombat caching is not a complete solution: a binding holding the original time span could continue counting, but refreshes, dispels, newly gained auras, and button reuse can invalidate cached state. Never label an extrapolated cached timer as verified current duration. The source-supported custom button refreshes its binding on duration updates, which is the lifecycle to emulate through supported APIs.

## Verification needed before calling this solved

1. On the actual Forever build, record the build/interface and feature availability. Configure a private formatter and native renderer. Demonstrate nonsecret `6300` seconds renders `105m`; check `6301`, `6299`, `3601`, `3600`, `3599`, `61`, `60`, `59`, zero, and an untimed aura to settle rounding and sub-minute policy.
2. Use a real long player buff with more than 90 minutes remaining. Record the same timer before, during, and after combat and across a minute transition. Confirm the duration becomes secret with a safe diagnostic; do not infer secret handling from a timer that remained public.
3. While in combat, refresh that buff, gain another long buff, remove one, and cause aura-button reassignment. The timer must follow its actual aura, rather than continuing a cached precombat duration. Cover a debuff with a nondefault time modifier separately.
4. Exercise hide/show duration, profile formatting changes, font/position settings, aura expiry, Edit Mode, and weapon enchants. Disable or release obsolete bindings so old and new renderers cannot compete for the same font string.
5. Save a combat video plus settings, build, addon revision, and error log as the repeatable artifact. A Lua mock can check lifecycle bookkeeping but cannot establish WoW taint/security compatibility. No such new in-game verification was performed for this research.

The existing [Forever combat verification note](forever-combat-verification.md) records a user-confirmed compact-native-text fix. It explicitly limits secret formatting to Blizzard's units. That existing evidence must not be upgraded into proof of a minutes-only solution.
